# مه‌گلد — فروشگاه مستقل React

نسخه مستقل React + Vite برای وب‌سایت و پنل مدیریت مه‌گلد. این شاخه برای سخت‌سازی و آماده‌سازی انتشار نگهداری می‌شود و به‌صورت خودکار روی دامنه اصلی منتشر نمی‌شود.

## اجرای محلی

1. Node.js نسخه 20 یا بالاتر نصب باشد.
2. فایل `.env.example` را به `.env.local` کپی کنید.
3. فقط مقادیر عمومی Supabase را در فایل محلی قرار دهید:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY` یا publishable key
4. اجرا:
   ```bash
   npm ci
   npm run dev
   ```

## امنیت و معماری

- مرورگر فقط از کلید عمومی Supabase استفاده می‌کند؛ کلید `service_role` نباید در کد فرانت‌اند یا فایل‌های قابل انتشار قرار گیرد.
- ثبت سفارش از Edge Function اختصاصی انجام می‌شود؛ JWT کاربر و تأیید حساب الزامی است.
- محاسبه مبلغ، اعتبار نرخ، بررسی قیمت مورد انتظار، کنترل اتمیک موجودی، رزرو ۱۵ دقیقه‌ای و idempotency در سمت سرور/دیتابیس انجام می‌شود.
- توابع حساس دیتابیس فقط برای `service_role` مجوز اجرا دارند.
- RLS برای جداول عمومی فعال است. دسترسی عمومی محصولات به ستون‌های نمایشی محدود شده و اطلاعات داخلی فرمول قیمت و شناسه ویرایشگر عمومی نیست.
- پنل مدیر به نقش مدیریتی، رکورد مجاز در `store_admins` و احراز هویت دومرحله‌ای TOTP با سطح `aal2` نیاز دارد.
- Edge Function ثبت سفارش علاوه بر کنترل JWT در کد، در سطح پلتفرم نیز `verify_jwt=true` دارد.
- کلیدهای API و اسرار ارائه‌دهندگان فقط باید در تنظیمات امن Edge Functions نگهداری شوند.

## وضعیت پرداخت

درگاه پرداخت آنلاین هنوز متصل و تأیید نشده است. سفارش ثبت‌شده فعلاً در وضعیت `awaiting_payment` قرار می‌گیرد و به معنی پرداخت یا فروش قطعی نیست. دیتابیس عمداً تغییر وضعیت به `paid` را تا زمان پیاده‌سازی و تأیید callback واقعی درگاه مسدود می‌کند. این محدودیت را حذف نکنید.

## مهاجرت‌های پایگاه داده

فایل‌های موجود در `supabase/migrations` شامل اصلاحات اخیر امنیتی این شاخه هستند. تاریخچه کامل مهاجرت‌های قدیمی پایگاه داده زنده هنوز به‌طور کامل در این مخزن بازسازی نشده است؛ بنابراین این شاخه در وضعیت فعلی یک بسته bootstrap کامل برای ساخت دیتابیس از صفر نیست. پیش از انتقال به پروژه جدید، باید baseline کامل schema، policyها، functionها، triggerها و migration history از پروژه اصلی استخراج و نسخه‌بندی شود.

## ساخت و کنترل کیفیت

CI روی شاخه سخت‌سازی اجرا می‌شود و این مراحل را بررسی می‌کند:

- نصب وابستگی‌ها با `npm install` و همگام‌سازی lockfile
- نصب قطعی با `npm ci`
- `npm run build`
- تولید و اعتبارسنجی فایل پیش‌نمایش مستقل

خروجی CI خصوصی است و انتشار خودکار روی دامنه اصلی انجام نمی‌دهد.

## پیش‌نیازهای انتشار عمومی

انتشار مشتری‌محور تا زمان تکمیل موارد زیر متوقف می‌ماند:

- فعال‌سازی و آزمون واقعی درگاه پرداخت و callback امن
- تکمیل اطلاعات هویتی فروشنده، نشانی، تلفن و صفحات حقوقی/حریم خصوصی/مرجوعی
- تأیید مجوزهای لازم برای مدل فعالیت فروش طلا و سکه در بستر آنلاین
- تکمیل MFA مدیر و فعال‌سازی محافظت گذرواژه‌های افشاشده در Supabase Auth
- تأیید دامنه، DNS، ایمیل فرستنده، SPF/DKIM/DMARC و آزمون تحویل ایمیل
- آزمون سرتاسری ثبت سفارش، رزرو، پرداخت، لغو، انقضای رزرو و بازگشت وجه در محیط آزمایشی
